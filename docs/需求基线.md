# 可复用游戏测试框架：需求基线 v1.0

状态：用户已确认  
确认日期：2026-10-02

## 目标

完成一个可公开展示、可复现、可在面试中解释的项目，体现游戏功能测试、自动化实现、缺陷定位和框架复用能力。

## 被测游戏与环境

- 主游戏优先验证 [Stendhal](https://github.com/arianne/stendhal)。接入成本过大时，允许替换游戏，保留五类重点业务和框架目标。
- 第二个游戏采用 [Shardy 井字棋](https://github.com/mopsicus/shardy-tictactoe)，接入少量用例验证公共能力复用。
- Mac 运行测试和本地服务端；两款游戏共用一种 Android 模拟器，固定系统版本和分辨率。

## 功能测试范围

五个系统深入覆盖正常、异常、边界和跨系统关联：**背包道具、任务奖励、商店货币、角色成长、地图战斗与独立挑战**。

另外十一组做基础功能覆盖：账号角色、NPC 对话、玩家交易、银行存储、社交组队、死亡复活、成就收藏宠物、采集生产、房屋婚姻、小游戏与活动、外观设置。部署后继续核对系统清单并补漏。

根据可重复性和结果验证能力，选择适合的用例自动化。

## 框架与执行

- Python 编写自动化用例，pytest 统一组织、执行和断言；Airtest 操作游戏界面。
- 各游戏提供自己的业务接口适配、操作步骤、断言和定位素材。
- 公共层复用配置、设备连接、接口调用机制、执行、日志和报告。跨游戏业务模板列为后续探索。
- 本地统一入口按游戏、模块、接口/UI测试选择执行；功能测试设计保留在文档中。

## 数据与规则

自动准备并恢复账号、角色、金币、道具和任务状态，支持重复运行。辅助能力用于准备、读取和恢复；购买、领奖等被测操作走真实业务流程。

业务断言记录预期及依据。说明与代码冲突时保留双方来源，相关用例标记“规则待确认”。

## 失败处理与诊断

连接中断、界面识别问题允许有限重试；业务断言失败直接记录。保留首次失败和每次尝试的证据，重试成功仍标记不稳定。

报告包含用例 ID、失败步骤、预期与实际、相关截图、接口消息、服务端日志、测试数据和复现方式，支持定位后手动单独重跑。

## 验收与交付

- 核心基准用例连续运行**多轮**（轮数按当前目的自定），无需人工干预，判定一致；重试单独统计。
- 独立实验版本注入可控缺陷，验证检出、定位及恢复后的回归；原版问题与注入问题分别标记。
- 原版真实缺陷交付复现证据、缺陷报告、原因分析和自动化回归用例。
- 交付公开代码仓库、需求与测试设计、系统覆盖清单、运行说明、报告样例、重复运行记录和演示视频。

## 启动前验证与暂缓事项

当前完成的是资料核查。正式实现前，需要验证服务端启动、Android 客户端连接、Airtest 操作、接口读取目标角色状态，以及数据准备和恢复。

具体版本、核心基准用例清单、重试上限在验证与测试设计阶段落实。使用者、维护者经验、人力和工期按此前决定暂缓讨论。
