# Stendhal 功能用例目录

版本基线：Stendhal 1.49，源码 commit `cbe0825e9b46f2a8adf9adce8c5747ece13b17a0`。本目录是可执行设计，不是执行报告；16 组是需求中的业务分组，不表示穷尽游戏内容。规则以固定源码和官方手册交叉核对，冲突保留并标记“规则待确认”。

## 执行约定

- `A`/`U`：已实现 API / Airtest 用例，仅代表该条用例。**不记录、也不要求轮数**——跑几轮由使用者按当前目的自定（冒烟 1 轮、改动验证按需、发布前多跑几轮），报告里各轮结果与是否一致照实记录即可，不存在"必须跑固定轮数才算验收"这回事。`A?`/`U?`：建议API/Airtest自动化，尚未实现/执行。`M?`：可按步骤手工执行，尚无执行证据。状态按用例记录，不能由同模块另一条PASS推导；最新证据集中在[验收清单](验收清单.md)。
- 业务操作必须由玩家会话/游戏界面执行。GM 只准备和读取状态；每次读写校验目标角色。正常操作也要核对服务端差量；拒绝用例同时核对拒绝响应和状态未变。
- 新NPC会话的首个业务关键词前统一发送`bye → hi <NPC名>`并确认响应，表中只写关键词的条目也遵守此步；报价后yes/no、重复确认或指定并发会话时不插入bye，以免改变待测状态。每个独立参数子例重新准备并建立会话。
- `R1`：保存并恢复当前 QaProbe 支持的背包/装备、任务、XP/HP/level/base_hp、karma、位置、NPC交易金额、looted_items及物品计数缓存、atk/def及其XP、kills/tutorial/visited/skills；核验恢复投影。原位置被占用时，只允许报告并核验同地图曼哈顿距离不超过1的相邻格。成就数据库、银行/其他容器、宠物、持续状态、世界实体需另做恢复；NPC attending/浏览器玩家会话也不在快照内，UI结束需真实bye并退出连接。不能只凭 `restored:true` 声称完整恢复；战斗rat专用夹具另清理rat/对应尸体。
- `R2`：独立本地服务环境，停服后备份该环境的 `database/`、持久世界状态和账号配置；每条用例执行后停服恢复备份、重启并重登核对。涉及动态岛/尸体/采集节点/银行/多角色/房产/成就时使用此方式；先完成一次恢复演练，才能进入无人干预多轮。此环境重置尚待实现自动化。
- `R3`：保存 Android Chrome 客户端设置/外观，结束后恢复并重启核对；外观服务端状态同时用 R2。账号创建使用一次性角色，结束注销会话；下一轮从 R2 的未创建基线开始。
- 所有待执行条目先保存前置状态、角色名、版本、操作输入、截图/对话/状态差量和恢复结果。异步结果等服务器处理完成；拒绝后观察至少 2 个服务器回合。连接/识别重试保留第一次证据；购买/领奖等动作结果不确定时先读状态，禁止直接重发。
- 下表中的 `N` 是前置记录的原数量，`M` 是原金币，`H` 是最大 HP。容量无 bag feature 时为 12 槽；不能把堆叠数量当槽数。API 边界输入按真实协议发送，不由辅助脚本代做。
- `equipToInventoryOnly`会遍历其他可达的合法槽/容器，不保证进入bag。下表“bag满导致拒绝/奖励落地”必须同时占满双手、禁止可访问交易槽/嵌套容器，money奖励子例还要无可用pouch；若预期只测试bag目标，动作应显式指定bag。
